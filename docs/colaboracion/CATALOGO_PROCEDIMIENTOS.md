# Catálogo de procedimientos compartidos

[Reglas compartidas](../REGLAS_COMPARTIDAS.md) → [Router](ROUTER_CONTEXTO.md) → [Flujo](FLUJO_TRABAJO.md) → procedimiento pertinente. Son documentos Markdown de lectura explícita, no Skills nativas instaladas.

| Procedimiento | Uso |
| --- | --- |
| [Desarrollo](../skills/desarrollo/PROCEDIMIENTO.md) | Arquitectura, alcance y preservación antes de editar código |
| [Pruebas y diagnóstico](../skills/pruebas-diagnostico/PROCEDIMIENTO.md) | Resultados reproducibles, fallos y limitaciones |
| [Gestión](../skills/gestion-proyecto/PROCEDIMIENTO.md) | Objetivos y estados con evidencia, sin porcentajes inventados |
| [Bitácora](../skills/bitacora/PROCEDIMIENTO.md) | Registro de cambios relevantes y siguiente acción |

Para cada cliente usa [Adaptadores manuales](ADAPTADORES_MANUALES.md). Para aprender el entorno consulta el [Manual maestro](../../cerebro/08_Manuales/00_INDICE_GENERAL.md).

## Ejemplos

- Router: «Lee el router y selecciona contexto para planificar selección de cámaras; no modifiques archivos».
- Desarrollo: «Aplica desarrollo al alcance autorizado; presenta ausencias antes de elegir arquitectura».
- Pruebas: «Aplica pruebas y diagnóstico a las comprobaciones documentales disponibles; distingue pruebas pendientes».
- Bitácora: «Registra esta sesión autorizada usando evidencia real, con autor pendiente si no está confirmado».

No uses estos ejemplos para ampliar autorización de una tarea ni para ejecutar operaciones remotas, instalar dependencias o publicar cambios.
